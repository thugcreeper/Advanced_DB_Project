# 所選科別／人員正數篩選修正

> 歷史紀錄：現行分頁、缺值與查詢快照行為見 [條件式 Modal 驗證](conditional-modal-2026-10-16.md)；舊固定分頁／完整 25 欄及初版正數篩選測試已退休。

日期：2026-10-16（Asia/Taipei）

原行為在類別已選、數量下限留白時，沒有施加數量條件，因此仍回傳所選數量為 0 的行政區。縣市條件有套用，但不符合使用者對「選類別即篩出有該類別」的預期。

經使用者確認，現在選定科別／人員後，所選 scope 的數量必須大於 0；兩項都選以 AND 篩選。未選類別不施加此條件。all 仍表示醫院與診所數量加總，不要求地區同時有兩類院所。

- 後端對未填下限、明確下限 0、缺值與 0 值皆正確處理；高於 1 的下限繼續生效。
- 前端選類別後預填 1，輸入欄最小值為 1；清空欄位仍送出 min=1。文字明示存在條件與加總語意。
- Java package：51 案，50 通過、1 未啟用的 Aura opt-in 略過、0 失敗。
- 實際 Aura 唯讀驗證：臺南未選類別為 37 區；急診醫學科 all 為 10 區且全數 specialty>0；護理師 all 為 37 區且全數 personnel>0；兩者同選為 10 區，與兩組結果交集完全一致。
- 驗證 hospital／clinic／all、明確 min=0、高下限、雙類別交集及不限制院所類型存在的行為。
- 桌面 1440px、手機 390px：臺南不選行政區，選科別後預設 1，清空仍送出 1，表格列與正數篩選結果一致。
- 進階條件收合的測試改以實際回應契約驗證，不再凍結與新規則衝突的舊筆數；錯誤提示定位到持續說明，避免與 snackbar 重複文字造成測試歧義。
